## 模块 1：自选清单（M2）

**实现状态**：✅ 2026-10-17（`src/cnwatch/watchlist/`，测试 `tests/test_watchlist.py`、`tests/test_cli.py`）

### 1.1 职责
维护用户股票池，绑定可信 `orgId`，为抓取层提供“每只股票一个请求”的输入。

### 1.2 输入
- CSV 文件：表头至少 `code,name,group`，可选 `note`；
- CLI 参数：`add/remove/edit/list/search/import`；
- 股票主数据快照：`data/snapshots/szse_stock.json`（`code/pinyin/category/orgId/zwjc`）。

### 1.3 输出
- `watchlist` 表行；
- `watchlist_audit` 每变更一行；
- 终端表格（`list`/`search`）。

### 1.4 数据结构
- `WatchlistEntry(code, name, pinyin, group, org_id, added_at, source, note, in_stock_master)`。
- 股票主数据加载为 `dict[code.upper(), StockMaster]`，`code` 统一大写后比对。

### 1.5 确定性纪律
1. `orgId` **只来自快照查表**；查不到即拒绝并提示“代码不在最新股票清单中”。禁止按代码推导。
2. `code` 六位数字校验；`group` 只允许三值；其他值退出码 2。
3. 检索规则固定：代码前缀匹配 > 中文名包含 > 拼音前缀；同分按代码升序。规则写进 docstring 并由测试锁定。
4. 快照换代：保留用户 `group/note/added_at/source`，只更新 `name/pinyin/org_id/in_stock_master`；消失代码置 `in_stock_master=0`。
5. 审计日志只追加，不更新不删除。

### 1.6 失败与退出码
| 情形 | 行为 | 码 |
|---|---|---|
| CSV 缺必需列 / 编码非 UTF-8 / 空文件 | 不导入任何行，报文件级错误 | 2 |
| CSV 某行分组非法 / 代码格式错 | 该行进“拒绝清单”并打印，其余行照常导入 | 1 |
| `orgId` 查不到 | 该行拒绝，提示不在快照中 | 1 |
| `add` 重复代码 | 默认拒绝并提示（`--update` 才覆盖） | 2 |

### 1.7 验收判据
- 三个 `orgId` 反例（`300750→GD165627`、`601398→jjxt0000019`、`002594→gshk0001211`）单测通过。
- 未知分组、缺 `orgId`、含 `<em>` 的标题按 `data/README.md` 反向样例白名单逐条覆盖。
- 快照换代测试：分组/备注不丢，消失代码被标记而非删除。
- 每次变更可用 `audit_id` 反查到旧值/新值/来源。

**M2 实现备注（2026-10-17）**

- CSV 必需列是 `code,group`；`name/note/org_id` 可选。带 `org_id` 时**必须与主数据一致**，
  否则该行拒绝 —— 这条比“缺 orgId 才拒绝”更严，因为一个错的 `orgId` 会静默抓到别家公司的公告。
- 行级拒绝（未知分组、代码格式、不在主数据）→ 其余行照常入库，退出码 1；文件级问题（缺列、非 UTF-8、空文件）→ 退出码 2 且一行不入。
- `list/search --audit` 是审计的查询入口；审计只追加。

## 模块 2：增量抓取与去重（M2）

**实现状态**：✅ 2026-10-17（`src/cnwatch/fetch/`，测试 `tests/test_fetch.py`、`tests/test_fetch_replay.py`）

### 2.1 职责
按自选清单逐只拉取公告，落库并去重，产出可审计的运行记录与失败清单。

### 2.2 输入
- `watchlist` 中 `in_stock_master=1` 的条目（`code + org_id`）；
- 上次成功游标（`fetch_runs` 中最近一次 `status in (complete, degraded)` 的 `window_end`）；
- 注入的 `Transport`、`Clock`、`Sleep`、`RateLimiter`。

### 2.3 输出
- `announcements` 新行；
- `fetch_runs` / `fetch_failures`；
- 终端摘要：`新增 N 条 / 请求 M 次 / 失败 K 只 / 结果完整|不完整`。

### 2.4 请求构造（实测口径）
```
POST http://www.cninfo.com.cn/new/hisAnnouncement/query
Content-Type: application/x-www-form-urlencoded
pageNum=<1..>
pageSize=30
column=szse
tabName=fulltext
plate=
stock=<code>,<orgId>
searchkey=
secid=
category=
trade=
seDate=<start>~<end>
sortName=
sortType=
isHLtitle=true
```

- `seDate` 起点 = 上次成功日期 − 1 天；终点 = 今天（`Clock` 提供）。
- 只认第一页的 `totalAnnouncement` 作为该股该窗口的总数；后续页按 `pageSize=30` 递增。
- 翻页终止：返回空页，或已累计 `>= totalAnnouncement`。
- `column` 固定 `szse`（单路径）；不按交易所分支。

### 2.5 去重与落库
- 解析 `announcements[]` 为 `Announcement`；标题先剥离 HTML 标签（正则 `</?[^>]+>` 后折叠空白）。
- `INSERT ... ON CONFLICT(announcement_id) DO UPDATE SET last_seen_at=excluded.last_seen_at`，其余字段不覆盖（防止上游改写标题污染历史）。
- `announcement_id` 为空或标题为空的条目**不落库**，计入 `dropped` 并点名 id（无 id 时点名 `code+date`）。

### 2.6 限频、重试、失败隔离
- 全局限流器：所有请求（含翻页、股票清单、PDF）共享同一个最小间隔。
- 可重试错误：超时、连接中断、5xx。不可重试：4xx、解析失败。
- 退避序列与最大次数取 `data/README.md` 第四节。
- 单只股票最终失败：写 `fetch_failures`，继续下一只；本轮 `status=degraded`。
- **接口声明总数与实取条数不符**：记该股失败（`total_mismatch`），不静默当成功。

### 2.7 首次基线与增量
- 无历史游标：窗口回看天数取 `data/README.md` 第四节的「首次回看天数」（M2 已补登记，代码解析该表，不另立口径）。
- 首次抓取结果全部标为基线，`report` 阶段不产生“新增”。
- 有游标：窗口按重叠 1 天计算，起点 = 上次成功运行的 `window_end` − 1 天。
- **只有 `status in (complete, degraded)` 且 `source_kind='watchlist'` 的运行才推进游标**：一次全失败不推进（否则留下永久盲区），全市场兜底不参与游标。

### 2.8 全市场兜底
- `fetch --all --date YYYY-MM-DD`：显式开关，`source_kind=market`，不写 `watchlist` 游标，不与清单增量混算。
- 结果在摘要中单列。

### 2.9 失败与退出码
| 情形 | 码 |
|---|---|
| 清单为空 / 无 `orgId` | 2 |
| 全部股票失败 | 1（`status=failed`） |
| 部分失败 | 1（`status=degraded`） |
| 全部成功 | 0 |

### 2.10 验收判据
- 请求次数 == 清单长度（不含翻页），翻页单独计数。
- 冻结响应回放两次：新增数与行数不变。
- 跨日重叠窗口：重复 0、漏报 0。
- 注入 5xx：重试次数 == 配置上限；失败清单点名该股；其余股票结果完整。
- 含 `<em>` 的样本入库后标题无标签。
- 声明总数与实取不符 → 该股失败，不产生半份结果。

**M2 实现备注（2026-10-17）**

- 日期换算按**交易所时区 UTC+8**，不是 UTC：冻结的 2026-10-15 有 922/1097 条在 UTC 下会落到前一天。
- 重试次数：配置解析会核对「退避序列长度」与「最多重试 N 次」是否一致；默认 1/2/4s 三个退避 = 共 4 次尝试。
- 回放（`--snapshots-dir`）不做限频等待：1s 间隔是为保护上游，回放不产生请求；限流器仍在链路上并计算等待值。
- 失败运行不推进游标；下一次运行仍是“首次”（基线）语义。

## 模块 3：类别规则引擎（M3）

**实现状态**：✅ 2026-10-17（`src/cnwatch/classify/`，测试 `tests/test_classify_engine.py`、`tests/test_classify_service.py`）

### 3.1 职责
把已落库条目确定性地映射为 `{category, tags[], risk_level}`。

### 3.2 输入
- `announcements` 行（只用 `title` 与 `code`；**不用正文**）；
- 规则包 `src/cnwatch/resources/rules/rules-v1.json`（M1 生成、冻结、入仓）。

### 3.3 规则包结构（M1 产出，此处为契约）
```json
{
  "rules_version": "v1",
  "official_categories": [
    {"id": "category_ndbg_szsh", "name": "年报", "patterns": ["年度报告"], "priority": 10}
  ],
  "keyword_patches": [
    {"id": "lawsuit", "name": "诉讼·仲裁", "patterns": ["诉讼", "仲裁"], "risk": "high"}
  ],
  "risk": {
    "high": ["category_tbclts_szsh", "category_tszlq_szsh"],
    "mid": ["category_yjygjxz_szsh"],
    "default": "low"
  }
}
```

约束：
- 26 个官方类别必须**全部存在**，与 `data/snapshots/new-notice.js` 抽出的枚举逐项对齐；
- `patterns` 必须由 M1 的实测样本佐证（每条规则至少一个真实标题命中）；
- 规则包由生成器产出，禁止手改；配“再生成逐字节一致”守门。

### 3.4 匹配算法
1. 标题归一：全角转半角、去除空白、去除 HTML 残留。
2. 官方类别：按 `priority` 升序、同优先级按 `id` 字典序，取**第一个命中**；多条命中时 `category` 取该条，其余记为 `also_matched`（仅日志，不进日报）。
3. 关键词补丁：独立扫描，全部命中进入 `tags[]`，按固定顺序（诉讼、减持、回购、质押）。
4. 风险级：收集**胜出类别**与**全部补丁标签**的 `risk`，取最高（high > mid > low）。
5. 未命中官方类别：`category="unclassified"`，风险按补丁结果；无补丁则 `low`。

> **M3 口径澄清（第 4 条）**：这里"命中项"指**胜出类别 + 补丁标签**，不含 `also_matched` 里的落选类别。
> 反证来自冻结真值台账本身：`南京晶升…2025年第一季度报告（更正版）` 同时命中一季报（low, 12）
> 与补充更正（mid, 68），台账期望 `low`。若按"所有命中项取高"，86 条里有 **8 条**会翻成 `mid`。
> 落选类别按第 2 条本来就"只进日志"，让它影响存储的风险级会自相矛盾。
> 该读法由 `tests/test_classify_engine.py::test_risk_uses_the_winning_category_not_every_match`
> 与整表逐条比对共同钉死；若将来要改成"取高"，必须先重新生成真值台账并同步 06/07。

### 3.5 确定性纪律
- 零 LLM、零随机、零相关性打分。
- `announcementType` 数值码**不参与**任何判定。
- 规则包版本写进 `classifications.rules_version`；同一版本 + 同一输入 = 同一输出。
- 规则命中数量、未分类数量在运行摘要中显式输出。

### 3.6 失败与退出码
| 情形 | 码 |
|---|---|
| 规则包缺失/版本不支持/26 类不全 | 2，不写任何分类结果 |
| 单条标题异常（超长/全空白） | 该条 `unclassified` 并计 `dropped_title`，继续 | 
| 未分类条目 > 0 | 仍是 0（这是正常结果，不是故障） |

### 3.7 验收判据
- 真值台账逐条比对 `category/tags/risk_level`，差异点名样本 id。
- 26 个枚举与 JS 快照逐项对齐（集合相等）。
- 四类补丁各有正例与反例（标题含词但语义无关的不命中）。
- 冲突样本：同时命中 high 与 low，输出 high。
- 同一输入双跑，产物逐字节一致。

### 3.8 M3 落地记录（2026-10-17）

| 项 | 落点 |
|---|---|
| 归一化 | `classify/text.py::normalize_title`；与 `tools/gen_rules.normalize` 在 6598 条冻结标题上逐条比对 |
| 规则包加载与校验 | `classify/rules.py`；格式/版本/26 类/四补丁/风险表/`announcement_type_used=false` 全部前置校验 |
| 匹配 | `classify/engine.py::classify_title`；匹配顺序由 `priority` 推导，不依赖文件顺序（文件是枚举顺序） |
| 存储 | `classify/repository.py`；单事务批量 upsert，`rules_version` 过期行自动重标 |
| 运行摘要与日志 | `classify/service.py::ClassifySummary`；`also_matched` 与 dropped 标题写 `out/logs/classify-<ver>.log` |
| CLI | `cnwatch classify [--since] [--resources]`；退出码 0（含 0 未分类）/ 2（规则包不可用） |

## 模块 4：本地日报（M4）

**实现状态**：✅ 2026-10-17

### 4.1 职责
消费抓取与分类结果，生成 Markdown + 单文件 HTML 日报，并维护日报基线。

### 4.2 输入
- 指定报告日 `--date`（默认取 `Clock` 的今天）；
- `announcements` + `classifications`；
- 前一日 `report_baseline_items`；
- `--generated-at`（可选注入）。

### 4.3 输出
- `out/reports/<date>/daily.md`
- `out/reports/<date>/daily.html`
- `report_runs` + `report_baseline_items`

### 4.4 章节结构（单一装配源，Markdown 与 HTML 共用）
```
1. 抬头：日期、生成时间、条目总数、失败股票数、数据来源声明
2. 摘要：high/mid/low 计数、未分类计数、新增数、消失数
3. 双视图 A：按股票分组（组内按风险级、日期、id 排序）
4. 双视图 B：按类别分组（官方类别 + 标签 + unclassified）
5. 与昨日对比：新增清单、消失清单（只列 id/标题/日期）
6. 未分类与异常：未分类条目、抓取失败清单、丢弃条目
7. 页脚：固定免责声明 + 数据来源
```

双视图一致性由**结构保证**：两个视图都从同一个 `list[Entry]` 分区函数输出，测试断言 `set(A ids) == set(B ids)`。

### 4.5 确定性纪律
- 渲染层**零判定**：不重算类别/风险/新增，只读既有字段。AST 门禁：`report/` 不得 import `classify` 的匹配函数。
- 排序键单点：`(risk_rank, announce_date desc, announcement_id asc)`，定义一次、两视图复用。
- 渲染资源零外链：无 `<link>`、外链 `<script>/<img>/<iframe>`、`@import`、外部字体；条目 `<a href>` 放行（内容字段）。
- HTML 为单文件，CSS 内联，无 JS 或仅内联脚本。
- 同输入 + 同 `--generated-at` = 逐字节一致（Markdown 与 HTML 各测一次）。
- 文件名不含时间戳；目录用报告日。

### 4.6 首次基线与对比
- `report_baseline_items` 中无前一日数据 → `baseline_created=1`，新增段写“首次运行，已建立基线”，**新增 = 0**。
- 有前一日基线：新增 = 今日集合 − 昨日集合；消失 = 昨日集合 − 今日集合。
- 消失只做计数与清单，不写 `removed_at`（该字段留给抓取层标记“上游不再返回”）。

### 4.7 失败与退出码
| 情形 | 码 |
|---|---|
| 数据库不存在 / 报告日无数据且无基线 | 2 |
| 本次抓取有失败股票 | 1（日报仍生成，抬头标注“不完整”） |
| 正常 | 0 |

### 4.8 验收判据
- 两视图 id 集合相等。
- 首次运行新增 = 0，且有明确说明。
- 两日冻结快照 → 新增/消失逐条一致。
- HTML 零外链断言（出口常驻）。
- 双跑逐字节一致（两格式）。
- 免责声明逐字存在。

### 4.9 M4 落地记录（2026-10-17）

| 项 | 落点 |
|---|---|
| 单一装配源 | `report/assembly.py::build_document`；两格式只做排版，`ReportDocument` 是唯一内容来源 |
| 双视图 | `assembly._partition` 一个分区函数供两视图；`test_both_views_carry_the_same_id_set` 断言集合相等**且逐组计数相等** |
| 排序键单点 | `models.Entry.sort_key` = `(risk_rank, -date_ordinal, announcement_id)`；日期转负序数，一次升序排序即得降序日期 |
| 仓库读取 | `report/repository.py`；`announcements INNER JOIN classifications`，未打标行不会被伪造成 `low` |
| 首次基线 | 无更早 `report_baseline_items` → `baseline_created=1`，`added=0`，正文写“首次运行，已建立基线” |
| 对比 | 集合差；消失只计数与列清单，**不写 `removed_at`** |
| 零外链 | `report/html.py::assert_no_external_resources` 在 `render_html` **内部**调用；`<a href>` 放行 |
| 零判定 | AST 门禁禁止 `report/` import `classify`；行为测试：库内存 `low`、标题含“质押”时报告仍打印 `low` |
| 双跑一致 | 同 `--generated-at` 两次运行，Markdown 与 HTML 各自 sha256 相同 |
| 报告日 | 默认 `Clock.exchange_today()`（UTC+8），非 UTC 日期 |
| 来源隔离 | `rows_for_date` 只取 `source_kind='watchlist'`；`fetch --all` 的全市场行不进日报（FR-18） |
| 未分类显示 | `labels.py` 的 `FALLBACK_NAMES` 把 `unclassified` 显示为“未分类”；未知 id 回落为 id 本身 |
| 未打标条目 | INNER JOIN 会让未打标行缺席两个视图；报告在“未分类与异常”里给出计数并提示 `cnwatch classify` |
| 退出码 | 0 正常；1 抓取有失败股票（日报仍生成，抬头标注“本次抓取不完整”）；2 无库 / 该日无数据且无基线 |
| CLI | `cnwatch report [--date] [--generated-at] [--resources]`；`--help` 尾注即免责声明 |

实测（`data/snapshots` 两日回放，20 只自选股）：

```
10-15  items 8   high 0 mid 4 low 4  unclassified 1   首次运行 → baseline_created=1, added 0
10-16  items 5   high 0 mid 0 low 5  unclassified 4   baseline 2026-10-15: added 5, removed 8
```

## 模块 5：归档与提醒（M5）

**实现状态**：✅ 2026-10-17（`src/cnwatch/archive/`、`src/cnwatch/notify/`，
测试 `tests/test_archive.py`、`tests/test_notify.py`）

### 5.1 职责
按用户显式请求下载 PDF 并抽取前 3 页文本；按配置发送提醒。

### 5.2 归档输入/输出
- 输入：`--announcement-id`、`--code`、`--category`、`--risk` 任一组合；`--all-high` 显式开关。
  四个筛选项以 AND 组合；**筛选项只覆盖 `source_kind='watchlist'`**（与日报同一条 FR-18 纪律），
  只有显式 `--announcement-id` 可以点全市场兜底里的行——那是用户在指名，不是规则在放大。
  没有任何筛选项 → 退出码 2（"按需"必须点得出名字）。
- 输出：`data/pdf/<code>/<date>/<announcement_id>.PDF`；`archive_records` 行（大小、时间、`text_status`、摘要）。
- 幂等口径（M5 落地时定）：同一 `announcement_id` 的记录存在且**文件大小与登记一致** → 不下载、不写第二行。
  文件缺失或大小不符 → 重下一份并**更新同一行**（自愈，仍不产生重复行）。

### 5.3 文本抽取
- 顺序：PyMuPDF → `pdftotext` → 不可用。
- 抽取是**显式请求**：`--text` 打开（`data/README.md` 第四节 `归档文本抽取` 行给出默认值，当前为"默认关闭"）。
  未请求时 `text_status=unavailable`、摘要为空——这是"没有文本"，不是"抽到了空文本"。
- 只抽前 3 页，取前 N 字符作为摘要（页数 N 单点定义于 `data/README.md` 第四节）。
- 两者都不可用且用户启用抽取：**退出码 2**，提示安装 `.[pdf]` 或系统 `pdftotext`，不写空摘要。
  该校验在第一次下载之前、创建任何目录之前完成，所以"没写任何东西"是结构性的，不是回滚出来的。
- PDF 能下载但抽取失败：`text_status=unavailable`，摘要为空，退出码 0（降级可识别）。
  后端返回空白（或只剩 NUL）同样记 `unavailable`，不冒充"抽取成功但摘要为空"。
- 摘要**不得**作为分类依据：`archive/` 不 import `classify`（AST 门禁），
  并由行为测试钉住"抽取内容里出现质押/减持/诉讼也不改动 `classifications` 行"。

### 5.4 提醒
- 渠道：`desktop` / `email` / `webhook`，默认 `none`（默认值从 `data/README.md` 第四节解析，不写在 argparse 里）。
- 发送失败：只写运行日志，不影响日报与 DB；退出码 1。
- 默认关闭时零外部调用（测试断言）：`none` 在 CLI 里**先返回**——不建运行时目录、不开库、
  不构造任何渠道对象；服务层再兜一层，`enabled` 为假时连库都不读。
- 消息内容来自当日已打标的 `watchlist` 条目（按风险排序，最多 10 条 + 其余计数），
  正文的免责声明取自 `cnwatch.disclaimer` 单点常量。
- 当日无条目 → 不发送，退出 0（没有值得提醒的事不是故障）。

### 5.5 验收判据
- 落盘路径与大小记录正确；重复归档同一 id 幂等。
- 依赖缺失 → 退出码 2 + 安装提示。
- 抽取失败 → `unavailable`，不伪造摘要。
- 通知失败不影响日报与 DB。
- `data/pdf/` 不在 git 跟踪范围。

常量集中在 `exit_codes.py`；CLI 映射唯一。
