## 一、一句话需求

给 A 股个人投资者一份**自选清单为输入、官方类别为骨架、本地日报为产物**的确定性公告筛选工具：每天只读自选池里真正需要看的几条公告，而不是翻几百份 PDF。

## 二、痛点 → 能力转译

| 用户的真实痛点 | 现状（竞品/手工） | 本工具的能力 | 可验证的交付证据 |
|---|---|---|---|
| 自选池几十只股票，逐只翻页面又慢又漏 | 手工逐只点开巨潮个股页 | 清单持久化 + 逐只增量抓取 | `cnwatch fetch` 的运行记录：每只成功/失败、请求数、新增数 |
| 抓下来一堆标题，仍不知道哪条重要 | 爬虫只负责下载，不分类 | 官方 26 类枚举 + 四类关键词补丁 + 风险分级 | `classify` 输出的 `category/tags/risk_level` 与真值台账逐条一致 |
| 每天真正关心的只有业绩预告、减持、诉讼、退市这类 | 人工通读 | 规则化筛选，`high/mid/low` 排序 | 日报按风险级置顶；规则表单点定义 |
| 不知道今天比昨天多了什么 | 无对比能力 | 昨日基线对比：新增 / 消失 | `report` 的对比段 + 两日冻结快照测试 |
| 第一次运行把历史公告全刷成“今日新增” | 无基线概念 | 首次运行静默建基线 | 首次运行样例断言“新增 = 0” |
| 公告原文链接要能点开 | 只给 PDF 文件名 | `adjunctUrl` 拼官方直链 | 每条带可点击原文链接；链接由实测路径拼接 |
| 不想依赖云服务/账号/大模型 | SaaS 或 LLM 方案 | 纯本地 CLI + SQLite，零 LLM | 断网回放可跑完整链路；无遥测、无账号 |

## 三、用户与场景

| 角色 | 场景 | 对工具的硬要求 |
|---|---|---|
| 个人投资者（持有 20–100 只） | 每天收盘后跑一次，看当天新增 | 单轮 < 60s；日报可双击打开；不要求常驻 |
| 投研助理 | 维护观察池，按类别/风险筛条目 | 清单增删改查、类别视图、审计日志 |
| 董秘办/合规岗 | 关注自家与同业的风险类公告 | 风险提示、诉讼、减持、质押必须显式标出 |
| 二次开发者 | 想复用抓取与规则结果 | 产物结构化、字段稳定、可机读、可离线回放 |

非目标用户：需要实时行情/交易/量化回测的人；需要全市场公告全文检索的人；需要云端多端同步的人。

## 五、边界与非目标

与 `plan/01-题目文档.md` 第六节一致，这里只列工程上的判定口径：

1. **不构成投资建议**：不输出利好/利空、不评级、不预测收益、不给买卖时点。风险级只是筛选优先级。
2. **不做行情、不做交易、不做模拟盘**。
3. **不做云同步、账号体系、遥测**；全部数据留在本机。
4. **不绕过验证码/登录**：只用公开查询接口，不伪造 Cookie。
5. **不再分发原文**：默认只存标题、日期、类别、链接；PDF 仅用户显式开启时本地落盘且不入库。
6. **类别边界**：26 类来自官方枚举；四类补丁只进 `tags[]`，不伪造官方类别；`announcementType` 数值码映射未核对前不参与分类。
7. **季节性边界**：年报/一季报/监事会在窗口内为 0 属披露季节性，不据此判故障。
8. **首期范围**：自选清单 + 增量抓取 + 26 类规则 + 双视图日报 + 按需归档/提醒；全市场扫描仅显式兜底；基金公告、港美股、全文检索不做。
9. **命名边界**：产品名不使用“巨潮/CNINFO”；数据来源统一写“数据来源：巨潮资讯网”。
