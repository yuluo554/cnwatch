# 10-17-cninfo-watch：A股公告关注看板（巨潮资讯网）

> **性质**：不参赛项目题（发布 GitHub 公开仓库，署名 yuluo554）
> **产出仓库**：`10-17-cninfo-watch`
> **版本**：v1（2026-10-17 定稿；全部实测结论的基准日均为 2026-10-17）
> **形态**：纯本地 Python CLI + 本地日报（Markdown + 单文件 HTML）；单进程 + SQLite，无服务器、无 GPU
>
> **定位宣言**：维护 20–100 只自选股 → 定时增量拉巨潮公告 → 按官方 26 类枚举 + 关键词规则打标 + 风险分级 → 生成"股票 × 类别"双视图本地日报。**只做公开信息聚合，不构成投资建议**。竞品都停在"爬虫/下载 PDF"层：没有人做"自选清单为输入 + 官方类别全集 + 本地日报产物"。

---

## 一、介绍

A 股个人投资者、投研助理与董秘办每天面对的是同一类噪声：自选池里几十只股票，公告一条接一条，PDF 一份接一份。真正需要当天看到的可能只有几条——业绩预告、减持、诉讼、风险提示、退市相关；其余大量日常经营、股东会、中介报告条目只是背景。人工逐只翻股票页面，既漏又慢；现有开源工具大多停在"抓取/下载 PDF"层，抓完不分类、不排序、不成日报，用户仍要自己从几百份文件里找重点。

本题要求做一个**纯本地、双击即跑**的 A 股公告关注看板：

- 输入是一份**自选清单**（20–100 只，分持仓/观察/风险三组），不是"全市场扫描"；
- 数据源是巨潮资讯网的公开查询接口，**逐只增量抓取**，`announcementId` 主键去重；
- 分类词表直接采用巨潮披露页面的**官方 26 类枚举**，再叠加诉讼/减持/回购/质押四类关键词补丁；
- 输出是**"股票 × 类别"双视图本地日报**（Markdown + 单文件 HTML），每条带标题、日期、类别、风险级与巨潮原文链接；
- 与昨日对比，新增/消失一目了然；首次运行**静默建基线**，不把历史公告刷成"今日新增"。

需求证据（检索留档，基准日 2026-10-17）：

- V2EX 2023-10-25 主题《什么AI能精简八股文公告》：公告噪声大，核心诉求是"筛选"而不是"生成"；
- V2EX 2024-08-05 股票信号提醒工具 idea：用户要的是"提醒我看什么"，不是再做一个行情终端；
- GitHub `miniQMT` issue #11（2026-09-25）："红利股息率监控 27 个标的动态提醒每周汇总"——自选池 + 动态提醒 + 定期汇总的形态已被真实用户提出；
- PanWatch（2128★，2026-10-16 仍在推送）：验证"自选池 + 提醒 + 自动报告"大类成立，但其路线重依赖 LLM；
- `youhaozhao/cninfo-mcp` issue #6（2026-09-08）：巨潮接口 504/502 被公开记录，说明这是有真实生产级依赖的接口，稳定性处理是刚需而不是假想。

开源空白（`gh api` 检索，基准日 2026-10-17，检索式为软论据、随题留档）：

| 检索式 | 结果 | 结论 |
|---|---|---|
| `巨潮 公告` | 24 条相关，最高 0★ | `ashare-announcement-board` / `cninfo-board` / `panda-board-data` 全是静态页或数据仓 |
| `cninfo announcement` | 262 条 | `startprogress/China_stock_announcement` 217★ 是 2020 年 Scrapy 项目，只抓不算；`gaodechen/cninfo_process` 86★ 做 PDF 关键字统计；`rollysys/use_cninfo` 32★（2026-05）按需抓取 + Markdown，**数据接入最接近，但没有清单/规则/日报** |
| `公告 监控 推送` | 20 条 | `Frankansty/listed-company-monitor` 1★，形态最接近（七类规则 + Excel 日报），但 Windows GUI、固定名单、无类别全集 |
| `自选股 看板` | 549 条 | `daily_stock_analysis`（66k★）是 LLM 分析综合系统，不是公告工具 |
| `公告 日报` | 14 条，最高 1★ | 无成型的"自选清单 → 分类日报"项目 |

**判定**：不存在 >5★ 的"自选清单 + 官方类别全集 + 本地日报"项目；形态已被 1★ 项目验证，差异必须做在**类别全集 + 增量看板 + 跨平台 CLI + 风险分级**。

竞品差异（写进题面的对标结论）：

- `CninfoDistributedSpider`（19★）：Scrapy + Kafka 分布式，需 Redis/Kafka；一次性指定公司；PDF 落盘；无分类规则；`pushed_at` 2019-10-24，已停更。
- 本题：单进程 + SQLite，双击即跑；自选清单持久化、增量轮询；分类日报 + PDF 链接；26 类规则 + 风险分级；`announcementId` 主键 + 游标 + 失败重试。

## 二、任务要求（首期 5 模块）

首期只做下面 5 个模块。自选清单规模按 20–100 只设计；全市场扫描只作为兜底能力，不是主路径。所有抓取数值口径（限频、重叠窗口、pageSize、退避、风险分级）**单一定义于 `data/README.md` 第四节**，本文只描述行为，若两处表述有出入以该表为准。

### 模块 1：自选清单管理

- **输入**：用户的 CSV 自选清单；CLI 增删改查命令；巨潮股票清单 `GET http://www.cninfo.com.cn/new/data/szse_stock.json`（实测 200，6261 条，字段 `code / pinyin / category / orgId / zwjc`；`category` 分布为 A股 6182、B股 78、CDR 1；`Last-Modified: 2026-10-16`）。文件名虽为 `szse_stock.json`，**实测含沪/深/北全部股票**；北交所另有 `GET .../new/data/bj_stock.json`（实测 604 条）可用于交叉校验。
- **输出**：本地自选清单表（代码、名称、拼音、分组、`orgId`、加入时间、来源）与一份**审计日志**（每次增删改记录时间、动作、旧值、新值、操作来源）。
- **确定性纪律**：
  - `orgId` **必须查表，禁止按代码推导**。实测反例：`300750` 的 `orgId` 是 `GD165627`（大写、非标准），`601398` 是 `jjxt0000019`，`002594` 是 `gshk0001211`。建 `code → orgId` 映射时统一转大写后再比对。
  - 支持按代码、中文名、拼音检索（使用清单里的 `zwjc` / `pinyin` 字段），匹配规则固定、可复现。
  - 分组为 `持仓 / 观察 / 风险` 三组，未知分组必须报错而不是静默归入默认组。
  - 股票清单文件是**快照**：更新映射时保留自选清单里用户手工维护的分组与备注；清单里已不存在的代码要显式标记"代码不在最新股票清单中"，不得静默删除。

### 模块 2：增量抓取与去重

- **输入**：自选清单中的每只股票（代码 + `orgId`）；上次抓取游标；公告查询接口 `POST http://www.cninfo.com.cn/new/hisAnnouncement/query`。
- **输出**：SQLite 中的公告条目；每轮抓取的运行记录（开始/结束、每只股票的成功/失败、请求次数、新增条数）；**本次失败清单**。
- **接口实测字段**（基准日 2026-10-17，响应 200，`totalAnnouncement: 1313`）：
  `announcements[].{secCode:"000001", secName:"平安银行", announcementId:"1225601360", announcementTitle:"关于副行长任职资格核准的公告", announcementTime:1791820800000, adjunctUrl:"finalpage/2026-10-13/1225601360.PDF", adjunctType:"PDF", announcementType:"01010503||010112||012303"}`。
- **确定性纪律（六条硬约束，逐条落进实现与测试）**：
  1. **清单必须逐只请求**。实测 `stock=000001,orgA;300750,orgB;600519,orgC` 只返回第一只；换顺序仍只认第一只；重复 `stock=` 参数同样无效。实测 5 只串行 1.31s（≈260ms/只），50 只≈13s、100 只≈26s；**以逐只串行 + 全局限频为准，不得写"批量参数"捷径**。
  2. **增量窗口必须重叠 1 天**。`announcementTime` 只有日期精度（时间部分为 `00:00:00`），按小时切窗会漏公告；每次查询的 `seDate` 起点 = 上次成功抓取日期 − 1 天，终点 = 今天。
  3. **去重主键 = `announcementId`**（SQLite 主键 / 唯一约束）；`announcementTime` 只当日期使用，不参与"同一时刻"判定。
  4. **`pageSize` 上限 30**（请求 100 实测只返回 30）；翻页直到返回空页或达到 `totalAnnouncement`，翻页之间同样受全局限频约束。
  5. **三交易所不写三套逻辑**。实测 `column=szse|sse|bj` 返回完全相同结果（同日均 1313 条，沪市 `600519`、北交所 `920000` 都能用 `szse` 查到）；`column=fund` 是独立基金库，不纳入本工具。
  6. **失败隔离与退避**。全局请求间隔 ≥1s；失败按指数退避重试（1s → 2s → 4s，最多 3 次）；单只股票最终失败只影响该只，必须写入"本次失败清单"，并在日报/终端提示"本次抓取失败 N 只，结果不完整"。接口曾出现 504/502（公开 issue：`youhaozhao/cninfo-mcp` #6，2026-09-08），不得把接口抖动当成"没有新公告"。
- **补充纪律**：
  - `searchkey` 查询会插入 `<em>` 高亮标签，入库前必须剥离；落库标题不得含 HTML 标签。
  - 全市场兜底：实测 2026-10-16 全天 1313 条、10-15 全天 1097 条；`pageSize=30` 时约 44 页、≈11s。兜底只在用户显式选择时运行，结果单独标记来源，不与自选清单增量混为一谈。
  - 首次运行只建基线（见模块 4），不产生"新增"告警。
  - 抓取层的外部交互（网络、时钟、睡眠）必须单点可注入，离线回放真实响应字节即可跑完整链路。

### 模块 3：类别规则引擎

- **输入**：已落库的公告条目；类别规则包（26 个官方类别枚举 + 关键词补丁规则）。
- **输出**：每条公告的 `{category, tags[], risk_level}`，其中 `risk_level ∈ {high, mid, low}`。
- **官方 26 类枚举**（来源：`https://static.cninfo.com.cn/new/js/app/disclosure/notice/new-notice.js`，实测 200，逐类 30 天量已核，基准日 2026-10-17）：

  | # | 枚举 | 中文 | # | 枚举 | 中文 |
  |---|---|---|---|---|---|
  | 1 | `category_ndbg_szsh` | 年报 | 14 | `category_zf_szsh` | 增发 |
  | 2 | `category_bndbg_szsh` | 半年报 | 15 | `category_gqjl_szsh` | 股权激励 |
  | 3 | `category_yjdbg_szsh` | 一季报 | 16 | `category_pg_szsh` | 配股 |
  | 4 | `category_sjdbg_szsh` | 三季报 | 17 | `category_jj_szsh` | 解禁 |
  | 5 | `category_yjygjxz_szsh` | 业绩预告 | 18 | `category_gszq_szsh` | 公司债 |
  | 6 | `category_qyfpxzcs_szsh` | 权益分派 | 19 | `category_kzzq_szsh` | 可转债 |
  | 7 | `category_dshgg_szsh` | 董事会 | 20 | `category_qtrz_szsh` | 其他融资 |
  | 8 | `category_jshgg_szsh` | 监事会 | 21 | `category_gqbd_szsh` | 股权变动 |
  | 9 | `category_gddh_szsh` | 股东会 | 22 | `category_bcgz_szsh` | 补充更正 |
  | 10 | `category_rcjy_szsh` | 日常经营 | 23 | `category_cqdq_szsh` | 澄清致歉 |
  | 11 | `category_gszl_szsh` | 公司治理 | 24 | `category_fxts_szsh` | 风险提示 |
  | 12 | `category_zj_szsh` | 中介报告 | 25 | `category_tbclts_szsh` | 特别处理和退市 |
  | 13 | `category_sf_szsh` | 首发 | 26 | `category_tszlq_szsh` | 退市整理期 |

- **关键词补丁（官方类别集里没有的四类）**：诉讼/仲裁、减持、回购、质押。30 天全市场 `searchkey` 实测：诉讼 238、业绩预告 128、回购 1095、减持 416；`category_gqbd_szsh` + `searchkey=减持` 命中 747，说明"类别 ∩ 关键词"可以叠加。补丁规则输出到 `tags[]`，不伪造官方类别。
- **确定性纪律**：
  - 分类完全规则化，**零 LLM、零相关性打分**；同一输入必须得到同一 `category/tags/risk_level`。
  - `announcementType` 数值码与 26 个枚举的映射**尚未建立（⬜ 待核对）**，不得据数值码猜类别。首期分类依据 = M1 用"逐类别查询"标定的标题规则 + 类别名的确定性关键词；规则包必须由实测样本佐证。
  - 未命中任何官方类别时输出显式 `unclassified` 并计数，**不得强行塞进某一类**。
  - 季节性空结果不判故障：30 天窗口内年报、一季报、监事会实测为 0，是披露季节性，不是接口坏。
  - 风险分级是**产品自定规则**（规则表见 `data/README.md` 第四节），不是监管评级，也不输出收益预测；规则优先级固定，冲突时 high > mid > low。

### 模块 4：本地日报

- **输入**：SQLite 中的公告与分类结果；当日抓取结果；昨日日报基线。
- **输出**：
  - Markdown 日报 + **单文件 HTML**（样式与脚本内联，零外部资源引用）；
  - **"股票 × 类别"双视图**：按股票分组展示，以及按类别分组展示，两边条目集合必须一致；
  - 每条包含：标题、公告日期、类别、风险级、巨潮原文链接；
  - 与昨日对比：新增条目、消失条目（消失只做计数与清单，不删除历史）；
  - 页脚固定声明："本工具仅聚合公开信息，不构成投资建议。"
- **确定性纪律**：
  - 渲染层**零判定**：只消费抓取结果与规则引擎结论，不在渲染时重算类别或风险。
  - **首次运行静默建基线**：没有历史基线时不输出"新增"，只写基线文件并在终端说明；第二次运行起才做昨日对比。
  - 原文链接由 `adjunctUrl` 拼成 `http://static.cninfo.com.cn/<adjunctUrl>`（实测该路径可直连，返回 `application/pdf`）；页面只放链接，不内嵌全文。
  - 同一天、同一数据输入重复生成，内容必须一致（允许显式 `--generated-at` 注入时间以保证可复现）。
  - 页面不得引用外链字体/脚本/样式；条目链接属于内容字段，不在"零外链"限制内。

### 模块 5：归档与提醒

- **输入**：用户显式标记需要归档的公告（按股票/类别/风险级/单条）；提醒配置。
- **输出**：
  - PDF 按需落盘到 `data/pdf/<code>/<date>/<announcementId>.PDF`，记录大小与抓取时间；
  - 文本摘要：用 PyMuPDF 或 `pdftotext` 抽取**前 3 页**关键段落；抽取失败降级为"仅标题"并在条目上标记 `text_status=unavailable`；
  - 通知渠道：桌面通知 / 邮件 / webhook **三选一配置**，默认 `none`（关闭）。
- **确定性纪律**：
  - **只做按需归档**，不做批量预下载；归档请求同样受全局限频约束。
  - 依赖缺失不得静默降级：用户启用文本抽取但 PyMuPDF/pdftotext 都不可用时，必须明确报"依赖缺失"并给出安装提示；"仅标题"只用于 PDF 能下载但文本层抽取失败的情况。
  - PDF 文本层质量实测不稳定：部分能抽片段，减持类 PDF 乱码；因此摘要不得作为分类依据，分类只依赖标题与规则。
  - 通知发送失败不得影响日报生成与数据库状态，只记运行日志。
  - 默认不把 PDF 与全文提交到仓库；`data/pdf/` 在 `.gitignore` 中。

### 首期验收口径

50 只自选股连续运行 7 天：

- 漏报 0：以巨潮原文逐条比对，窗口内应抓到的公告一条不少；
- 重复 0：`announcementId` 唯一约束生效，重复运行不产生重复行；
- 单轮 < 60s（逐只请求 + 全局限频下可达成）；
- 失败可重试且状态可见：运行记录能看出哪只失败、重试几次、本次结果是否完整；
- 日报可由数据库与规则包完全复现，关闭通知后核心链路仍可跑。

## 六、边界与非目标

- **只做公开信息聚合，不构成投资建议**：不荐股、不评级、不预测收益、不给买卖时点。
- **不做行情**：不接 K 线、分时、技术指标、资金流；不做任何价格分析。
- **不做交易**：不下单、不接券商账户、不做模拟盘。
- **不做云同步**：无账号体系、无云端存储、无遥测；全部数据留在本机。
- **不绕过验证码/登录**：只使用公开可访问的查询接口，不逆向登录态、不伪造 Cookie。
- **不再分发原文**：默认只存标题、日期、类别与链接；PDF 仅在用户显式开启时下载到本地，且不入库、不再分发；不把巨潮全文或 PDF 提交到仓库。
- **商标与命名**：产品名不使用"巨潮/CNINFO"作为名称；数据来源统一描述为"数据来源：巨潮资讯网"。
- **类别边界**：26 类来自官方枚举；诉讼/减持/回购/质押是关键词补丁，不冒充官方类别；`announcementType` 数值码映射未核对前不参与分类。
- **季节性边界**：年报、一季报、监事会在特定窗口为 0 属正常披露季节性，不据此判定接口故障。
- **品牌隔离**：本仓库独立命名、独立文档、独立数据，不复用其他项目的代码与文案，不在文档中提及其他项目。
- **首期范围限定**：只做自选清单（20–100 只）+ 增量抓取 + 26 类规则 + 双视图日报 + 按需归档/提醒；全市场扫描仅作显式兜底，基金公告、港美股、公告全文检索不在首期。
