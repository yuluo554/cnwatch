## 一、总体形态

单进程 CLI + SQLite + 本地文件产物。无服务器、无 Redis/Kafka、无 GPU、无账号体系。

```
┌──────────────────────────────────────────────────────────┐
│ cli.py  参数解析 / 退出码 / 编码守卫（零业务判定）          │
└───────────────┬──────────────────────────────────────────┘
                │ 调用
┌───────────────▼──────────────────────────────────────────┐
│ app/  编排层（每模块一个服务，纯函数优先）                  │
│  watchlist · fetch · classify · report · archive · notify │
└───────┬───────────────────────┬──────────────────────────┘
        │                       │
┌───────▼─────────┐   ┌─────────▼──────────────────────────┐
│ store/          │   │ infra/                             │
│ SQLite schema   │   │ clock · http transport · ratelimit │
│ repositories    │   │ paths · encoding · archive         │
└─────────────────┘   └────────────────────────────────────┘
```

分层纪律：

1. **CLI 只做参数解析、调用与退出码映射**，不含任何业务判定。
2. **app 层不直接读环境**：时钟、睡眠、HTTP、路径全部通过参数注入。
3. **report 渲染层零判定**：只消费 `classify` 与 `fetch` 的既有结论，不重算类别/风险/新增。
4. **store 层不写业务规则**：只负责 schema、约束、事务与查询。

## 三、技术选型

| 维度 | 选择 | 理由 | 弃选 |
|---|---|---|---|
| 语言 | Python ≥ 3.8 | 跨平台、标准库足够、用户机器普遍可用 | Node/Go（用户安装门槛更高） |
| HTTP | `urllib.request` + 自定义 `Transport` | 零第三方依赖；可注入离线回放 | `requests`（多一个运行时依赖） |
| 存储 | SQLite（标准库 `sqlite3`） | 单文件、事务、唯一约束、无需服务 | JSON 文件（并发/去重弱） |
| CLI | `argparse` | 标准库、退出码可控 | click/typer（引入依赖） |
| 测试 | `pytest`（仅 dev extra） | 生态成熟 | unittest（样板多） |
| PDF 文本 | PyMuPDF 优先，`pdftotext` 兜底（可选 extra） | M5 才需要；核心链路不依赖 | 纯标准库解析 PDF（不可靠） |
| 打包 | 源码 + `pip install -e .` | 纯 CLI，冻结收益低 | PyInstaller（D17 弃） |
| 调度 | 不内置，README 给 cron/任务计划示例 | 避免常驻进程与跨平台差异 | 内置 scheduler |

## 四、依赖与安装面

```toml
dependencies = []                       # 核心零第三方
[project.optional-dependencies]
dev = ["pytest>=7.4"]                   # 测试期
pdf = ["PyMuPDF>=1.23,<1.25"]           # 可选：3.8 兼容上界
```

- **核心链路（清单、抓取、分类、日报）只用标准库**。
- `pdf` extra 只服务 M5 文本抽取；缺失时显式报“依赖缺失”，不静默产出空摘要。
- 运行时若需要随包资源，放 `src/cnwatch/resources/` 并声明 `package-data`，避免“源码态能跑、安装后找不到数据”的安装面缺口。
- `data/` 是证据与输入台账，不是安装面资源；`pip install -e .` 的源码形态下按仓库相对路径解析，README 明示该限制。

## 五、数据模型（SQLite schema v2）

DDL 与 `src/cnwatch/db.py` 中的 `SCHEMA_SQL` 必须逐字一致；改 schema 走版本号 + 迁移，不手改运行库。
v1 → v2（M2）只给 `fetch_runs` 增列：`source_kind`、`pages`、`dropped`、`baseline_created`。
`db.initialize` 对 v1 库就地 `ALTER TABLE` 补齐并改写版本号，已有行不丢；
更高版本号直接报错，不尝试猜迁移。

```sql
CREATE TABLE schema_info (
    key   TEXT PRIMARY KEY NOT NULL,
    value TEXT NOT NULL
);

CREATE TABLE watchlist (
    code            TEXT PRIMARY KEY NOT NULL CHECK (length(code) = 6),
    name            TEXT NOT NULL CHECK (length(trim(name)) > 0),
    pinyin          TEXT NOT NULL DEFAULT '',
    group_name      TEXT NOT NULL CHECK (group_name IN ('持仓', '观察', '风险')),
    org_id          TEXT NOT NULL CHECK (length(trim(org_id)) > 0),
    added_at        TEXT NOT NULL,
    source          TEXT NOT NULL,
    note            TEXT NOT NULL DEFAULT '',
    in_stock_master INTEGER NOT NULL DEFAULT 1 CHECK (in_stock_master IN (0, 1))
);

CREATE TABLE watchlist_audit (
    audit_id  INTEGER PRIMARY KEY AUTOINCREMENT,
    at        TEXT NOT NULL,
    action    TEXT NOT NULL CHECK (action IN ('add', 'remove', 'edit', 'import')),
    code      TEXT NOT NULL,
    old_value TEXT,
    new_value TEXT,
    source    TEXT NOT NULL
);

CREATE TABLE announcements (
    announcement_id   TEXT PRIMARY KEY NOT NULL CHECK (length(trim(announcement_id)) > 0),
    code              TEXT NOT NULL CHECK (length(code) = 6),
    name              TEXT NOT NULL,
    title             TEXT NOT NULL CHECK (length(trim(title)) > 0),
    announce_date     TEXT NOT NULL CHECK (length(announce_date) = 10),
    adjunct_url       TEXT NOT NULL DEFAULT '',
    adjunct_type      TEXT NOT NULL DEFAULT '',
    announcement_type TEXT NOT NULL DEFAULT '',
    source_kind       TEXT NOT NULL CHECK (source_kind IN ('watchlist', 'market')),
    first_seen_at     TEXT NOT NULL,
    last_seen_at      TEXT NOT NULL,
    removed_at        TEXT
);
CREATE INDEX idx_announcements_code_date ON announcements(code, announce_date DESC);
CREATE INDEX idx_announcements_date ON announcements(announce_date DESC);

CREATE TABLE classifications (
    announcement_id TEXT PRIMARY KEY NOT NULL
                    REFERENCES announcements(announcement_id) ON DELETE CASCADE,
    category        TEXT NOT NULL,
    tags_json       TEXT NOT NULL DEFAULT '[]',
    risk_level      TEXT NOT NULL CHECK (risk_level IN ('high', 'mid', 'low')),
    rules_version   TEXT NOT NULL,
    classified_at   TEXT NOT NULL
);

CREATE TABLE fetch_runs (
    run_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    started_at    TEXT NOT NULL,
    finished_at   TEXT,
    window_start  TEXT NOT NULL,
    window_end    TEXT NOT NULL,
    source_kind   TEXT NOT NULL DEFAULT 'watchlist'
                  CHECK (source_kind IN ('watchlist', 'market')),
    stocks_total  INTEGER NOT NULL DEFAULT 0,
    stocks_ok     INTEGER NOT NULL DEFAULT 0,
    stocks_failed INTEGER NOT NULL DEFAULT 0,
    requests      INTEGER NOT NULL DEFAULT 0,
    pages         INTEGER NOT NULL DEFAULT 0,
    inserted      INTEGER NOT NULL DEFAULT 0,
    dropped       INTEGER NOT NULL DEFAULT 0,
    baseline_created INTEGER NOT NULL DEFAULT 0
                     CHECK (baseline_created IN (0, 1)),
    status        TEXT NOT NULL CHECK (status IN ('running', 'complete', 'degraded', 'failed'))
);

CREATE TABLE fetch_failures (
    run_id     INTEGER NOT NULL REFERENCES fetch_runs(run_id) ON DELETE CASCADE,
    code       TEXT NOT NULL,
    attempts   INTEGER NOT NULL DEFAULT 0,
    last_error TEXT NOT NULL,
    PRIMARY KEY (run_id, code)
);

CREATE TABLE report_runs (
    report_date      TEXT PRIMARY KEY NOT NULL,
    generated_at     TEXT NOT NULL,
    markdown_path    TEXT NOT NULL DEFAULT '',
    html_path        TEXT NOT NULL DEFAULT '',
    item_count       INTEGER NOT NULL DEFAULT 0,
    baseline_created INTEGER NOT NULL DEFAULT 0 CHECK (baseline_created IN (0, 1)),
    failed_stocks    INTEGER NOT NULL DEFAULT 0,
    content_sha256   TEXT NOT NULL DEFAULT ''
);

CREATE TABLE report_baseline_items (
    report_date     TEXT NOT NULL,
    announcement_id TEXT NOT NULL,
    PRIMARY KEY (report_date, announcement_id)
);

CREATE TABLE archive_records (
    announcement_id TEXT PRIMARY KEY NOT NULL,
    local_path      TEXT NOT NULL,
    byte_size       INTEGER NOT NULL CHECK (byte_size >= 0),
    downloaded_at   TEXT NOT NULL,
    text_status     TEXT NOT NULL CHECK (text_status IN ('extracted', 'unavailable')),
    text_excerpt    TEXT NOT NULL DEFAULT ''
);
```

设计要点：

- `announcement_id` 为 `TEXT PRIMARY KEY NOT NULL`，空串也被 CHECK 拒绝；不使用可空唯一键（SQLite 中 NULL 彼此不相等，会让重复入库绕过唯一索引）。
- 日期字段统一 `YYYY-MM-DD` 文本；时间戳统一 ISO 8601 文本，由注入的 `Clock` 产生。
- `fetch_failures` 以 `(run_id, code)` 为主键，天然做到“同一轮同一只股票只记一行”。
- `fetch_runs.source_kind` 把全市场兜底与清单增量分开记：游标查询只认
  `source_kind='watchlist'` 且 `status in (complete, degraded)` 的行，`--all` 永远不会
  把清单的增量游标推到全市场日期上。
- `fetch_runs.pages` 与 `requests` 分开记：`requests == 清单长度` 的验收只对首请求成立，
  翻页与重试另计，混在一起就无法证明“逐只请求”没有被批量捷径替代。
- `baseline_created` 钉在运行记录上：首次运行存了 N 条但“新增”为 0，这两个数必须能同时查到。
- `report_baseline_items` 保存每日条目 id 集合，次日对比是集合差，不做文本 diff。
- `removed_at` 只用于“消失”标记，不删除历史（FR-33）。

## 六、统一条目模型

抓取、分类、日报之间只传一个不可变模型（`fetch/models.py`，M2 落地）：

```python
@dataclass(frozen=True)
class Announcement:
    announcement_id: str
    code: str
    name: str
    title: str            # 已剥离 HTML 标签
    announce_date: str    # YYYY-MM-DD，仅日期
    adjunct_url: str      # 原样保存相对路径
    adjunct_type: str
    announcement_type: str
    source_kind: str      # watchlist | market

    @property
    def source_url(self) -> str:
        return "http://static.cninfo.com.cn/" + self.adjunct_url
```

分类结果是独立不可变模型：


## 七、CLI 契约

```
cnwatch [--home PATH] <command> [options]

命令：
  watchlist   自选清单管理（M2）
  fetch       逐只增量抓取（M2）
  classify    规则打标（M3）
  report      生成日报（M4）
  archive     按需归档 PDF（M5）
  notify      发送提醒（M5）
  run         端到端编排（未实现，保留退出码 3）
  selftest    环境与安装面自检（M0 已实现）
```

> **M5 注记**：`run` 早先写作"M4 交付了 report；run 本身顺延到 M5"，但 M5 的 DoD
> （`plan/06` M5 与 `plan/04` 模块 5）只覆盖归档与提醒，M5 已交付 `archive`/`notify`。
> `run` 因此仍是唯一带退出码 3 的命令：它要串联的 `fetch`/`classify`/`report` 已各自可用，
> 这个 3 只表示"编排那层还没人需要"，不表示链路缺失。见 `plan/06` M5 偏差。

退出码（锁进测试，后续重构不得漂移）：

| 码 | 语义 | 典型场景 |
|---|---|---|
| 0 | 完成 | 正常结束、自检通过 |
| 1 | 降级完成 | 部分股票抓取失败、日报结果标注不完整；规则引擎有未分类项不算降级 |
| 2 | 用法/输入错误 | 未知命令、参数缺失、未知分组、CSV 不可用、路径不存在 |
| 3 | 阶段未就绪 | 命令属于尚未实现的里程碑；**只打印说明，不写任何伪造产物** |

`3` 是**临时语义**：每个模块落地时从 `cli.STAGE_NOT_READY` 移除对应条目，并同步 CLI 帮助、README 状态表与测试；全部落地后该常量整项退役。

## 八、注入点（离线可测的根基）

| 注入点 | 生产实现 | 测试实现 |
|---|---|---|
| `Transport` | `urllib.request.urlopen`（带超时） | 回放冻结响应字节（`ReplayTransport` / `ScriptedTransport`） |
| `Clock.now()` | 系统 UTC 时间（`SystemClock`） | 固定时间（`FixedClock`，`--today` 亦可注入） |
| `Sleep(duration)` | `time.sleep`（`RealSleep`） | 记录调用不真睡（`RecordingSleep`）；回放用 `NullSleep` |
| `RateLimiter` + 单调时钟 | `SystemMonotonic` | `FakeMonotonic`（随 sleep 前进，可断言间隔） |
| `paths` | `--home` / `CNWATCH_HOME` / CWD | `tmp_path` |
| `data/` 位置 | `--data-dir` / `CNWATCH_DATA` / `$HOME/data` / 检出目录 | 同上，或显式目录 |
| PDF 文本抽取器 | PyMuPDF / `pdftotext` | 桩函数 |

规则：`app/` 与 `fetch/` 模块的函数签名显式接收上述依赖，禁止在函数体内直接读 `time.time()`、`datetime.now()`、`os.environ` 或发网络请求。
`tests/test_fetch.py::test_fetch_reads_no_system_clock` 以源码扫描守住这一条。

## 九、确定性策略

1. **时间**：所有落库/产物时间来自 `Clock`；日报支持 `--generated-at` 显式注入。
2. **顺序**：条目排序键固定为 `(announce_date DESC, announcement_id ASC)`，单点定义在 report 层。
3. **序列化**：JSON 产物 `sort_keys=True, ensure_ascii=False, indent=2`，LF 行尾，结尾换行。
4. **随机**：全项目禁止 `random`；需要采样时用显式 seed 的自研序列或固定清单。
5. **双跑**：同一输入两次生成 Markdown/HTML 必须逐字节一致（M4 测试）。

## 十、错误分类

| 类别 | 处理 | 退出码 |
|---|---|---|
| 用法错误（未知命令/参数、非法分组） | 立即拒绝，打印可操作提示 | 2 |
| 输入不可用（CSV 缺列、清单为空、路径不存在） | 拒绝运行，不建库不写产物 | 2 |
| 单只股票抓取失败（超时/5xx/解析失败） | 重试后记入失败清单，其余继续 | 1（本轮） |
| 接口声明总数与实取条数不符 | 硬失败，不落半份快照 | 1 |
| 可选依赖缺失（PyMuPDF/pdftotext 都不可用且用户启用文本抽取） | 明确报依赖缺失与安装提示 | 2 |
| 功能所属里程碑未实现 | 打印说明 | 3 |
